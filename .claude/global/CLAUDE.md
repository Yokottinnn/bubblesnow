# 最上位ルール（全プロジェクト共通・例外なし）

## 終わっていない作業があるなら、次の一手を必ず AskUserQuestion（ダイアログ）で出す

**判定の基準は「選択肢を書いたかどうか」ではない。「まだ終わっていない作業があるかどうか」。**

未完了の作業が 1 件でも残った状態でターンを終えるなら、**必ず AskUserQuestion を使う**。
地の文・箇条書き・表で選択肢を並べて「どれにしますか？」と聞くのは**禁止**。

**平文だけで一方的に会話を終えてよいのは、残作業がゼロで、利用者が次に何も
決めなくてよいときに限る。**

これは最上位ルールであり、**これを破ってよい例外は一切ない**。
急いでいても、選択肢が2つでも、話の流れ上自然に見えても、例外にしない。
プロジェクトを問わず、どのリポジトリで作業していても適用する。

### 対象になる場面（すべてダイアログ）

- **次のステップ・残件・未完了の作業を提示するとき**（疑問符が無くても対象）
  「残っているのは A と B と C です」と本文に並べて相手に選ばせるのは違反

- **他者・外部イベント待ちで止まるとき**
  待つこと自体が選択であり、待つ以外の道（別手段・先に別作業・中止）を選べる状態にする。
  「結果が出たら報告します」「完了を待ちます」で終えるのは違反

- 「A / B どちらにしますか」と尋ねるとき
- 「進め方の選択肢は次の3つです」と並べるとき
- 表やリストで案を比較して選ばせようとしているとき
- 「どれで進めますか？」「どうしますか？」で終わる文を書こうとしたとき

### 判定方法

**返答を送信する前に確認する**:
「この返答は、ユーザーに何かを選ばせようとしているか？」
「このターンで作業は終わり切ったか？」
→ 前者が YES、または後者が NO なら、**文章で選択肢を書かず AskUserQuestion を呼ぶ。**

選択肢を文章で書き始めたら、その時点で手を止めてツール呼び出しに切り替える。

### 例外にならないもの（よくある言い訳）

- 「ダイアログが流れた/答えてもらえなかった」→ 文章で並べ直すのではなく、**もう一度ダイアログで出す**
- 「選択肢が明らかだから」→ それでもダイアログ
- 「補足として書いただけ」→ 選ばせているならダイアログ
- 「技術的な比較表だから」→ 選択を促すならダイアログ
- 「作業報告なので選択肢ではない」→ 残作業があるならダイアログ

### 言い換えて回避するのは、選択肢を本文に並べるより悪い

フックに差し戻されたとき、**検知語を避けて書き直すのは違反である。**
差し戻しは「書き方を直せ」ではなく「ダイアログを出せ」という指示。

実際に起きた回避の例（すべて違反）:

- 「残件」「次のステップ」を消して「〜まで進みません」と言い換えた
- 「どうしますか？」を消して「連絡をもらえた時点で再開します」と言い換えた
- 「結果が出たら報告します」と書いて外部イベント待ちのまま終えた
- 判断をユーザーに委ねたまま、疑問符だけ削って言い切りの形にした

いずれも**残作業がある状態でダイアログを出していない**点で同じ違反。
差し戻されたら、文面ではなく AskUserQuestion を出すことで応じる。

### ダイアログの作り方

- 推奨があれば**先頭**に置き、ラベルに「(推奨)」を付ける
- 各選択肢の `description` に、選んだ結果どうなるか・費用・リスクを書く
- 「やらない」「後回しにする」も選べるようにする。待つ以外の道を必ず残す

### 例外にしてよい唯一のケース

**残作業がゼロで、かつ選択を求めていない**とき。つまり:

- 単に事実・状態・結果を報告していて、次にやることが何も残っていない
- 参考情報として比較を示すだけで、次の行動を選ばせていない

判断に迷ったら**ダイアログを使う**。使いすぎて困ることはない。

---

この規則は `~/.claude/settings.json` の `UserPromptSubmit` と `Stop` フックでも
機械的に強制している。文書に書くだけでは守られないことが実証済みのため、二重にしている。
