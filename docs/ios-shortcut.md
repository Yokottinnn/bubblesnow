# iOS ショートカットからタスクを追加する

## なぜページを開くのをやめたのか

これまでは `add.html`（→ `add-direct.html`）を Safari で開いて書き込んでいた。
DB を認証必須にすると、この経路はブラウザの認証状態に依存する。
そして iOS の ITP は**7日間開かないサイトのストレージを破棄する**ので、
たまにしか使わないページほど「またログイン」に当たりやすい。

ショートカットは HTTP リクエストを直接送れる。**ブラウザを経由する必要がない。**

```
ショートカット ──POST──> Firebase REST (?auth=シークレット)
```

シークレットはショートカットの中、つまりあなたの端末の中に置く。
公開ソースには出ない。ページの読み込みが無くなるぶん速くもなる。

## なぜ inbox に書くのか

`tasks` は**配列**で、アプリは配列として読み書きしている。
REST の POST は push キー（`-Nxxxx`）を作るので、`tasks` に直接 POST すると
配列がオブジェクトに変わり、アプリの前提が壊れる。

そこで受け口を `users/yokota/inbox` に分けた。
**アプリを開いたとき**に `tasks` へ移して inbox を空にする。

表示するのはアプリなので、「見た時点で入っている」なら十分。

## 設定

### 1. シークレットを用意する

`docs/firebase-security.md` の手順3で取得した database secret を使う。

### 2. ショートカットを作る

**ショートカット** アプリ →「+」→ 以下を追加。

**① テキスト**（タスク名を受け取る）
- 「共有シートから受け取る」を有効にするか、「入力を要求」を追加

**② URLの内容を取得**
- URL:
  ```
  https://nydaytodo-e0f20-default-rtdb.asia-southeast1.firebasedatabase.app/users/yokota/inbox.json?auth=ここにシークレット
  ```
- 方法: **POST**
- 本文を要求: **JSON**
- 本文のフィールド:

  | キー | 型 | 値 |
  |---|---|---|
  | `name` | テキスト | ①のテキスト |
  | `category` | テキスト | `その他` |
  | `priority` | テキスト | `🟡中` |
  | `status` | テキスト | `active` |
  | `createdAt` | テキスト | 現在の日付（ISO 8601） |

  `deadline` `detail` `url` `location` `icon` も同じ要領で足せる。

**③ 通知を表示**（任意）
- 「追加しました」など。成功したか分かるようにしておく

### 3. 確かめる

ショートカットを実行してからアプリを開く。タスクが増えていれば成功。

うまくいかないときは②の応答を通知に出す。
`{"name":"-Nxxxxx"}` のような push キーが返っていれば書き込めている。
`Permission denied` ならシークレットが違う。

## 旧 URL について

`add.html` と `add-direct.html` は残してある。ブラウザから使う分にはそのまま動く
（サインイン済みのセッションが要る）。ショートカットを移行したら、
そちらは使わなくてよい。

## シークレットの扱い

- ショートカットは iCloud で同期される。共有リンクを作らないこと
- 漏れたら Firebase Console で無効化して再発行する。アプリ側は Google サインインなので影響を受けない
