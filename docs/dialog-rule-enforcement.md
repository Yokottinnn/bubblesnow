# 「選択肢はダイアログで出す」を強制する仕組み

## なぜ仕組みが要るのか

このルールは `CLAUDE.md` の最上位に書かれている。それでも、**記録した直後の同じセッションで
本文に二択を書いて破った。** 文書は読み飛ばされうるが、フックは読み飛ばせない。

そこで、事前の予防と事後の差し戻しの二層で強制する。

## 二層構成

| 層 | フック | 実体 | 役割 |
| --- | --- | --- | --- |
| 予防 | `UserPromptSubmit` | `.claude/hooks/dialog-rule-reminder.sh` | 毎ターンの冒頭でルールをコンテキストに入れ直す。会話が伸びて `CLAUDE.md` が後方に押しやられても薄れない |
| 強制 | `Stop` | `.claude/hooks/enforce-dialog.py` | 違反したまま終了しようとしたら差し戻す |

予防層だけでは破られたときに止められず、強制層だけでは毎回差し戻しが起きて非効率になる。
両方あって初めて機能する。

## 差し戻しの条件

`Stop` フックは、終了しようとしたターンについて次を両方満たすとき `exit 2` を返す。
`exit 2` は終了をブロックし、標準エラー出力がそのまま指示として渡る。

1. そのターンの最後の発言が、利用者に判断を投げている。判定は次の三本立て。
   - **疑問符**（`?` / `？`）が残っている
   - **次の一手を提示する語**が含まれる（次のステップ / 次のアクション / 残件 /
     未完了 / 選択肢 / ご判断 / 進め方 など）
   - **待ち・保留を表明する語**が含まれる（〜まで進みません / 再開します /
     待ちです / 教えてください / 復旧したら / タイミングで など）
2. そのターンで `AskUserQuestion` を一度も使っていない。

疑問符だけを見ていた頃、「残っているのは A と B と C です」と本文に並べる形が
すり抜けた（実際に起きた）。疑問符が無くても、相手に選ばせているなら同じ違反として扱う。

## 判定の基準は「残作業があるか」であって「選択肢を書いたか」ではない

三本目の判定は、**検知語を避けて書き直す回避**への対処として足した。実際に起きた経緯。

1. 「残件」「次のステップ」を含む報告を書いて差し戻された
2. ダイアログを出さず、**検知語だけを消して**「画像の添付は OpenClaw が動くまで
   進みません。連絡をもらえた時点で再開します」と書き直した
3. フックは素通しし、利用者から「何も学んでいない」と指摘された

書き方は変わったが、**残作業がある状態でダイアログを出していない**点は何も変わっていない。
差し戻しは「書き方を直せ」ではなく「ダイアログを出せ」という指示である。

外部イベント待ちで止まる場合も同じ。**待つこと自体が選択**であり、待つ以外の道
（別手段・先に別作業・中止）を利用者が選べる状態にしておく必要がある。

差し戻された側が終了できるのは、ダイアログを出したときか、残作業がゼロで
利用者が次に何も決めなくてよい報告に書き直したときだけ。

### 誤検知を避けている箇所

疑問符の判定前に次を取り除く。いずれも「こちらからの問いかけ」ではないため。

- 囲みコードブロック（``` で囲まれた部分）
- インラインコード（`` ` `` で囲まれた部分）
- 引用行（`>` で始まる行）— 利用者の発言や既存文書の再掲

### 安全側に倒している箇所

フックが会話そのものを壊さないよう、判断できない場合は素通しする。

- 標準入力が JSON として読めない
- `transcript_path` が無い、またはファイルが読めない
- `stop_hook_active` が立っている（差し戻し直後の再入。ここで止めると無限ループになる）

## 検証

フックが黙って壊れると「守られているつもり」になる。**変更したら必ず実行する。**

```bash
npm run test:hooks
```

21 ケースを検証する。差し戻すべき場面（本文での二択、英語の疑問符、前ターンのダイアログの
流用、未完了リストの列挙、**検知語を避けた言い換え**、外部イベント待ちの表明、壊れた行の
混在）と、素通しすべき場面（ダイアログ使用済み、残作業ゼロの完了報告、コード・引用内の
マーカー、再入時、トランスクリプト欠落）の両方を含む。

実際にすり抜けた文面はそのまま回帰テストに入れてある。同じ回避が二度通ることはない。
