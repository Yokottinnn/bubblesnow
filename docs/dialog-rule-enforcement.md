# 「選択肢はダイアログで出す」を強制する仕組み

## なぜ仕組みが要るのか

このルールは `CLAUDE.md` の最上位に書かれている。それでも、**記録した直後の同じセッションで
本文に二択を書いて破った。** 文書は読み飛ばされうるが、フックは読み飛ばせない。

そこで、事前の予防と事後の差し戻しの二層で強制する。

## 二層構成

| 層 | フック | 実体 | 役割 |
| --- | --- | --- | --- |
| 予防 | `UserPromptSubmit` | `.claude/hooks/dialog-rule-reminder.sh` | 毎ターンの冒頭でルールをコンテキストに入れ直す。会話が伸びて `CLAUDE.md` が後方に押しやられても薄れない |
| 強制 | `Stop` | `.claude/hooks/enforce-dialog.py` | 違反したまま終了しようとしたら差し戻す |

予防層だけでは破られたときに止められず、強制層だけでは毎回差し戻しが起きて非効率になる。
両方あって初めて機能する。

## 差し戻しの条件

`Stop` フックは、終了しようとしたターンについて次を両方満たすとき `exit 2` を返す。
`exit 2` は終了をブロックし、標準エラー出力がそのまま指示として渡る。

1. そのターンの最後の発言が、利用者に判断を投げている。判定は次の二本立て。
   - **疑問符**（`?` / `？`）が残っている
   - **次の一手を提示する語**が含まれる（次のステップ / 次のアクション / 残件 /
     未完了 / 選択肢 / ご判断 / 進め方 など）
2. そのターンで `AskUserQuestion` を一度も使っていない。

疑問符だけを見ていた頃、「残っているのは A と B と C です」と本文に並べる形が
すり抜けた（実際に起きた）。疑問符が無くても、相手に選ばせているなら同じ違反として扱う。

差し戻された側は、ダイアログで聞き直すか、疑問符を消して言い切るまで終了できない。

### 誤検知を避けている箇所

疑問符の判定前に次を取り除く。いずれも「こちらからの問いかけ」ではないため。

- 囲みコードブロック（``` で囲まれた部分）
- インラインコード（`` ` `` で囲まれた部分）
- 引用行（`>` で始まる行）— 利用者の発言や既存文書の再掲

### 安全側に倒している箇所

フックが会話そのものを壊さないよう、判断できない場合は素通しする。

- 標準入力が JSON として読めない
- `transcript_path` が無い、またはファイルが読めない
- `stop_hook_active` が立っている（差し戻し直後の再入。ここで止めると無限ループになる）

## 検証

フックが黙って壊れると「守られているつもり」になる。**変更したら必ず実行する。**

```bash
npm run test:hooks
```

12 ケースを検証する。差し戻すべき場面（本文での二択、英語の疑問符、前ターンのダイアログの
流用、壊れた行の混在）と、素通しすべき場面（ダイアログ使用済み、言い切り、コード・引用内の
疑問符、再入時、トランスクリプト欠落）の両方を含む。
